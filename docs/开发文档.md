# 网络五子棋开发文档

## 1. 项目概述

项目名称：网络五子棋

开发语言：Java

JDK 版本：JDK 21

界面技术：`java.awt`、`javax.swing`、Java2D

网络技术：TCP Socket、多线程、文本协议

数据存储：MySQL、JDBC

构建方式：Gradle

项目根目录：`D:\service\AAA-JAVA\gomoku`

## 3. 分层设计

### model 包

保存不依赖界面的基础数据：

- `Stone`：空位、黑棋、白棋枚举
- `Point`：棋盘坐标
- `Move`：落子记录
- `ChatMessage`：聊天记录
- `GameMode`：本地双人、人机、联机模式

### core 包

- `Board`：15 乘 15 棋盘和五连判断
- `GameSession`：一局棋的轮次、历史、胜负和悔棋
- `MoveResult`：落子结果

五连判断使用四个方向向量：

```text
水平：(0, 1)
垂直：(1, 0)
正斜：(1, 1)
反斜：(1, -1)
```

每落一子，只检查经过该点的一条横线、一条竖线和两条斜线。

### ai 包

`GomokuAI` 使用评分表法：

1. 如果棋盘为空，下中心点。
2. 只收集已有棋子两格范围内的候选点。
3. 检查 AI 是否存在一步获胜点。
4. 检查玩家是否存在一步获胜点。
5. 对每个候选点分别按 AI 进攻和玩家威胁评分。
6. 将进攻分、防守分和中心位置分相加，选最高分。

评分表包括五连、活四、冲四、活三、眠三、活二等棋型。

### player 包

`Player` 是抽象类，`HumanPlayer` 和 `ComputerPlayer` 继承它。该结构体现了面向对象中的抽象、继承、方法重写和多态。

### network 包

- `NetworkMessage`：Socket 文本协议
- `NetworkListener`：客户端回调接口
- `OnlineClient`：客户端 Socket 和读线程
- `ProtocolException`：协议异常

消息字段使用 URL 安全的 Base64 编码，避免聊天内容中的换行、竖线等字符破坏协议。

主要消息类型：

```text
REGISTER
REGISTER_RESULT
LOGIN
LOGIN_RESULT
ONLINE_USERS
MATCH_RANDOM
MATCH_TARGET
MATCH_WAITING
MATCH_INVITE
MATCH_INVITE_RESPONSE
MATCH_CANCEL
MATCH_TIMEOUT
MATCH_CANCELLED
MOVE
CHAT
UNDO_REQUEST
UNDO_RESPONSE
UNDO_RESULT
TURN
RESTART_REQUEST
RESTART_RESPONSE
START
GAME_END
PEER_LEFT
ERROR
INFO
```

### 账号和大厅流程

1. 客户端建立 Socket 后发送 `REGISTER` 或 `LOGIN`。
2. 服务器通过 `AccountRepository` 查询 MySQL 中的 `player_account` 表。
3. 登录成功后 `GomokuServer` 将用户名登记到在线用户表，并广播 `ONLINE_USERS`。
4. 随机匹配把玩家放入等待队列，匹配成功或等待 60 秒后结束。
5. 固定匹配按用户名找到在线玩家，转发 `MATCH_INVITE`，对方接受后创建房间。
6. 房间建立后，服务器发送 `START`，其中包含双方用户名、黑方名称、白方名称和己方棋色。

### server 包

- `GomokuServer`：监听端口、接受连接、安排房间
- `ClientHandler`：每个客户端对应一个处理线程
- `GameRoom`：一局联机棋的权威状态

服务器使用房间锁保护棋盘状态。每个客户端连接拥有独立发送锁，避免多个线程同时写同一条 Socket 输出流。

服务器是联机对局的权威状态来源：

- 客户端只发送落子坐标
- 服务器判断轮次和位置是否合法
- 服务器广播落子结果
- 服务器判断胜负
- 服务器处理悔棋申请和重新开始申请

### database 包

- `DatabaseSettings`：读取数据库配置
- `DatabaseInitializer`：启动时自动建库建表
- `DatabaseManager`：JDBC 连接管理
- `AccountRepository`：账号注册、登录和最近登录时间
- `GameRepository`：保存对局、落子和聊天

数据库初始化步骤：

1. 使用不带库名的 JDBC URL 连接 MySQL。
2. 创建配置对应的数据库。
3. 使用带库名的 JDBC URL 重新连接。
4. 执行 `src/main/resources/sql/init.sql`。

数据库初始化失败不会阻止程序启动，错误会打印到控制台。这样在未安装 MySQL 时，仍可用于演示单机和人机功能。

### replay 包

`ReplayFileService` 使用简单文本文件保存和读取回放。

文件格式：

```text
# GOMOKU_REPLAY_V1
MODE=LOCAL_AI
BLACK=玩家
WHITE=电脑
WINNER=BLACK
MOVE=7,7,BLACK,1770000000000
```

### ui 包

- `GameFrame`：主窗口和业务事件协调
- `BoardPanel`：棋盘绘制和鼠标点击
- `BoardTheme`：棋盘背景主题
- `ReplayDialog`：对局回放

界面更新统一通过 `SwingUtilities.invokeLater` 回到事件派发线程。

## 4. 多线程设计

项目使用以下线程：

- Swing 事件派发线程：处理按钮、鼠标和界面更新
- 服务器接受连接线程：执行 `ServerSocket.accept()`
- 服务器客户端线程：每个客户端一个 `ClientHandler` 线程
- 客户端读取线程：持续读取服务器消息
- AI 计算线程：单线程执行器，避免阻塞 Swing 界面
- 数据库保存线程：对局结束后异步保存

共享数据使用 `synchronized` 或并发集合保护。

## 5. Socket 协议示例

逻辑消息：

```text
MOVE, 7, 7
```

实际发送：

```text
<Base64类型>\t<Base64行>\t<Base64列>
```

字段解码后由客户端或服务器处理。协议使用换行作为消息边界。

## 6. 胜负判断

`Board.findWinningLine` 对落子点执行：

1. 获取四个方向。
2. 从落子点向正负两个方向收集同色棋子。
3. 保存连续棋子坐标。
4. 如果数量大于等于 5，返回获胜连线。

界面根据返回的坐标绘制红色连线。

## 7. 悔棋设计

本地模式直接调用 `GameSession.undoLastMove()`。

人机模式回退到玩家最近一次落子之前，避免电脑刚下完就立即恢复电脑回合造成死循环。

联机悔棋由服务器处理：

1. 请求方发送 `UNDO_REQUEST`。
2. 服务器记录请求者并转发给对手。
3. 对手发送 `UNDO_RESPONSE`。
4. 同意后服务器回退一步。
5. 服务器广播 `TURN`。
6. 双方更新轮次。

## 8. 数据库表

### game_record

保存对局编号、模式、双方名称、胜者、总步数和时间。

### game_move

保存落子序号、行列坐标、棋色和时间。

### chat_message

保存联机聊天发送者、内容和时间。

### player_account

保存注册用户名、SHA-256 加盐后的密码摘要、盐值和最近登录时间。密码不会以明文写入数据库。

外键均设置 `ON DELETE CASCADE`，删除对局时会同时删除落子和聊天。

## 9. 异常处理

- 数据库异常：初始化时捕获并打印，后续保存失败也不会导致界面崩溃
- 网络异常：客户端通知界面断开，服务器移除对应客户端
- 协议异常：返回错误消息或忽略无法识别的消息
- 文件异常：保存或读取回放失败时弹出提示
